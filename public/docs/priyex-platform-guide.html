Workflow 01 • Infrastructure

Multi-Tenant Architecture & Data Perimeter Isolation

Strict cryptographic tenant isolation with dynamic domain resolution

Priyex HRMS operates as a true multi-tenant Cloud HCM. Every client organization operates within a distinct logical tenant boundary. All persistent database records (employee rosters, biometric logs, salary registers, identity documents) are strictly bound to a tenant foreign key, enforced at the query level by Hibernate Session filters and Spring Security perimeters.

Architectural Pillars
1. Logical Schema Isolation Tenant identifier indexing ensures sub-millisecond multi-tenant queries without database proliferation overhead.
2. Domain Detection Engine Dynamic DNS and email domain lookups route user requests directly to corresponding organizational profiles.
3. White-Label Branding Independent branding injection dynamically loads client company logos, legal names, and primary color palettes.
4. Rapid Workspace Provisioning Automated database seeding provisions statutory defaults, base holiday calendars, and organization hierarchies in under 60 seconds.
Operational Execution Sequence
Phase Primary Actor Execution & System Action
1. Tenant Provisioning SaaS Administrator New client profile registered with corporate name, company code (e.g. TCS, WIPRO), and email domains. System creates tenant record and seeds standard leave and tax schemas.
2. Domain Binding Tenant Admin Corporate email domains (e.g., @company.com) bound to tenant profile, enabling zero-confusion client routing on the public portal.
3. Policy Customization HR Operations Configures shift timings, biometric geofence radius, and approval escalation tiers cached in memory for high-performance execution.
Core REST Endpoints
GET /api/v1/tenant/detect-domain?domain={corporateDomain} GET /api/v1/tenant/validate-company?code={companyCode} GET /api/v1/tenant/branding
Security Perimeter Note: Cross-tenant database queries are blocked unconditionally at the repository layer. Direct attempts to pass another tenant's entity identifier return HTTP 403 Forbidden with security logging.
Workflow 02 • Identity & Security

Identity Resolution, SSO & Cryptographic JWT Authentication

Stateless token authentication with automated domain-to-organization resolution

Authentication requires validation of three security parameters: Organization Code, Corporate Work Email, and Password / SSO SAML Assertion. The system executes domain verification, evaluates BCrypt credential hashes against the tenant's user table, and issues signed JSON Web Tokens (JWT) containing company context and assigned authorization claims.

Execution Journey
Step Actor Technical Operations
1. Email Resolution User User inputs corporate email. UI analyzes the domain, matches it against known tenant domains or calls the detection API, and auto-populates the verified Organization Code.
2. Credential Verification Auth Engine Evaluates password hash against tenant records. Verifies account status is active and not locked due to prior failed attempts.
3. Token Generation Gateway Issues cryptographic HMAC-SHA512 JWT access token. User is routed to their role-specific dashboard.
Security Specifications
Confidentiality Policy: SuperAdmin credentials and internal infrastructure tokens are never transmitted to client viewports. All administrative accounts require individual multi-factor authentication (MFA).

Workflow 04 • Workforce Operations

Biometric Attendance, Geofencing & Shift Rosters

Hardware IoT synchronization and GPS perimeter validation

Dual-channel presence capture reconciles physical biometric terminals (ZKTeco, Essl) with mobile GPS clock-ins. Geofencing algorithms calculate Euclidean distance between the employee's coordinate and the company office center, validating punches within 50m to 500m perimeters.

Shift Rules & Regularization
Grace Period Tolerance Default 15-minute grace period accommodates transit delays before logging late-in penalties.
Shift Roster Mapping Supports Morning, General, Night, and rotational shifts with automated night shift allowance calculations.
Attendance Regularization Employee submits justification for off-site client meetings; reporting manager approves with full audit logging.
Continuous Daily Status Instant classification into Present, Half-Day, Absent, or On-Duty reflected immediately in payroll.
Workflow 05 • Compensation & Tax

Continuous Calculation Engine (CCE) & Statutory Indian Payroll

Real-time gross-to-net computation with EPF, ESI, PT, and Section 115BAC TDS

The Priyex Continuous Calculation Engine (CCE) calculates earnings, statutory deductions, and income taxes continuously with every shift punch rather than in end-of-month batch runs. It guarantees 100% compliance with Indian labor and tax statutes.

Statutory Formula Engine
Statutory Component Employee Share Employer Share Statutory Ceiling / Rules
EPF (Provident Fund) 12% of Basic 12% (3.67% EPF + 8.33% EPS) Wage ceiling ₹15,000/month for statutory minimum.
ESIC (State Insurance) 0.75% of Gross 3.25% of Gross Applicable when gross wage ≤ ₹21,000/month.
Professional Tax (PT) State Slab (e.g. ₹200) Nil State-specific slabs (e.g. Maharashtra ₹2,500/year, Karnataka ₹200/mo).
Income Tax TDS Per Slab Calculation Nil Dual Engine: Section 115BAC (New Regime) vs Old Regime (80C/80D/HRA).
Key Payroll Outputs
• Automated Electronic Challan cum Return (ECR) for EPFO portal upload • Bank NEFT/RTGS batch file formatting for 1-click corporate salary disbursement • Digitally signed PDF payslips delivered directly to employee mobile & web portals • Annual Form 16 Part A & Part B generation for income tax return filing

Workflow 08 • Offboarding

Digital clearance matrix, notice period calculation, and statutory gratuity engine

Governs employee departures with standardized cross-departmental clearances: IT hardware retrieval, Finance expense clearance, and Admin building access revocation. Automates statutory Gratuity calculation: (15 × Last Drawn Basic × Years of Service) ÷ 26.

Workflow 09 • Security & Compliance

Role-Based Access Control (RBAC) & Enterprise Governance

Principle-of-least-privilege matrix, immutable audit trails, and SOC 2 alignment

Five discrete authorization tiers enforce least-privilege security across the platform:

Role Identifier Operational Scope Primary Authorizations
SUPER_ADMIN Platform Infrastructure Tenant provisioning, platform performance monitoring, global system health. No tenant confidential business inspection.
ADMIN Tenant Executive Organization settings, company-wide policy definitions, department setup, audit trail review.
HR_ADMIN People Operations Employee onboarding, leave approval escalations, payroll processing, statutory remittances.
MANAGER Team Supervision Direct report attendance approvals, leave request sign-offs, shift roster scheduling, performance reviews.
EMPLOYEE Self-Service (ESS) Personal profile updates, biometric punch logs, payslip downloads, leave applications, tax declarations.
Immutable Audit Logging: Every state alteration (salary revisions, profile updates, manual punches) generates an immutable audit record logging actor ID, source IP address, UTC timestamp, and before/after values for SOC 2 Type II compliance.
